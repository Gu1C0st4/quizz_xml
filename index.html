01 · O que é

XML: uma árvore de dados que humanos e máquinas leem

XML (eXtensible Markup Language) é um standard da W3C de 1998 para estruturar dados de forma hierárquica, independente de como são guardados ou transmitidos. Não traz semântica — define estrutura e conteúdo, não comportamento.

STANDARD

Da W3C

Uma forma comum de comunicar entre sistemas com software e hardware diferentes.

TEXTO

ASCII / UTF-8

Legível e partilhável; estruturado por tags, ao contrário de texto plano.

ÁRVORE

Hierárquico

Um elemento raiz e elementos filhos ordenados (DOM — Document Object Model).

BASE

Extensível

HTML, SVG, OOXML, RSS, SOAP, Maven, Android... todos assentam em XML.

Anatomia de um documento


      

      

        
raiz
Um único elemento envolve todo o documento: rede.

        
elementos
Representam entidades ou valores: estacao, nome, localizacao.

        
atributos
Qualificam o elemento: id, lat, lon, disponiveis.

        
ordem
A ordem dos filhos faz parte do documento e pode ser imposta pelo XSD.

      

    

  






  

    

      02 · Sintaxe
      
Bem formado: cinco regras essenciais

      
Bem formado descreve a sintaxe. Ainda não garante que os dados respeitam o contrato do domínio — isso é tarefa do XSD.

    

    

      
1
Uma raiz
Existe exatamente um elemento raiz a envolver tudo.

      
2
Fecho correto
Cada tag aberta é fechada, ou é vazia com />.

      
3
Aninhamento
Os elementos não se cruzam; abrem e fecham por ordem.

      
4
Maiúsculas
<Nome> e <nome> são elementos diferentes.

      
5
Aspas
Os valores dos atributos ficam sempre entre aspas.

      
+
Comentários
<!-- ... --> como em HTML; nunca antes da declaração.

    


    

      

        
● Desafio: encontra os quatro problemas

        

      

      

        
Pista: verifica aspas, maiúsculas/minúsculas, fecho de elementos e quantidade de raízes.

        

          Ver a correção
          

            
1. Atributo sem aspas → atualizadaEm="2026-09-25".

            2. Maiúsculas trocadas → <nome>...</nome>.

            3. Elemento não fechado → <bicicletas disponiveis="12"/>.

            4. Segunda raiz → <estado> tem de ficar dentro da única raiz.

            

          

        

      

    

  






  

    

      03 · Modelação
      
Elementos ou atributos?

      
Não há regra universal: a consistência e o contrato importam mais. Mesmo assim, há boas heurísticas.

    

    

      
USA ELEMENTOS PARA

        
Conteúdo principal, estruturas repetidas, valores extensíveis e dados que podem vir a ganhar subestrutura.

      
USA ATRIBUTOS PARA

        
Identificadores, metadados compactos e propriedades simples que qualificam um elemento.

    

    

      

        
Mesma informação, 3 formas<data>22 Outubro 2020</data>

        
com subelementos<data><a>2020</a><m>10</m><d>22</d></data>

        
com atributo<data formato="ISO-8601">2020-10-22</data>

      

    

  






  

    

      04 · Validação
      
XSD descreve o contrato

      
Um documento bem formado pode continuar errado para o domínio (id vazio, preço negativo…). O XSD é um ficheiro .xsd separado que define as regras que o .xml tem de obedecer.

    

    

      
ESTRUTURA
Elementos, atributos e hierarquia.

      
ORDEM
sequence, choice e all.

      
CARDINALIDADE
minOccurs e maxOccurs.

      
TIPOS
string, integer, decimal, dateTime…

      
RESTRIÇÕES
limites, padrões, tamanhos, enumerações.

      
REUTILIZAÇÃO
simpleType e complexType nomeados.

    


    

      

        
Ligar o XSD ao XML

        

        
Nota: a associação no XML é apenas uma pista para ferramentas. A aplicação pode escolher explicitamente o esquema usado na validação.

      

      

        
Tipos simples ganham significado

        

          
xs:string
Rossio

          
xs:integer
12

          
xs:decimal
40.6575

          
xs:boolean
true

          
xs:date
2026-09-25

          
xs:dateTime
...T09:30:00Z

        

        
Em XSD, decimais usam ponto e datas seguem o formato ISO 8601.

      

    


    
Restrições: criar um tipo do domínio

    

      

      

        
aceite
0 · 12 · 80

        
rejeitado
-1 · 81 · doze

        
pattern
Expressão regular: PT-[A-Z]{3}-[0-9]{2} para o id da estação.

        
enum
Conjunto fechado: operacional | manutencao.

      

    


    
Compositores & cardinalidade

    

      
SEQUENCE
A → B → C
Todos aparecem pela ordem declarada.

      
CHOICE
A ou B
Escolhe uma das alternativas.

      
ALL
A + B + C
Qualquer ordem; em XSD 1.0 cada um ocorre 0 ou 1 vez.

    

    

      
1..1
obrigatório, uma vez

      
0..1
opcional

      
0..*
lista opcional

      
1..*
lista não vazia

    


    
Tipos complexos e tipos nomeados (reutilização)

    

      

      

        
sequence
Impõe a ordem dos filhos.

        
attribute
Qualifica o tipo complexo; use="required".

        
nomeado
Um complexType name="..." define-se uma vez e reutiliza-se em vários elementos.

        
ref
Permite referenciar elementos/atributos globais e dividir o XSD.
